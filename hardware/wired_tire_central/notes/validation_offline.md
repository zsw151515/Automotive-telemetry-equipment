# 离线软件验证与决策记录

日期：2026-10-23。范围：用户明确“尚未备齐，先完成离线软件”。这是离线研发版本，硬件矩阵 A–F 均未通过。

## 软件验证

- 原生 C++17：59 个命名用例通过，包含解析、分区、调度、BLE 编码、SPI、年龄、渲染，以及真实 ProbeLink/RaceChronoBle 方法的状态机回归。
- Python 工具：10 个用例通过，包含只读抓包工具、缺失输入拒绝、完整打包、SHA256 和硬件 profile 排除。
- Arduino CLI 1.5.0、Arduino-ESP32 3.3.7：C3/P4 离线编译检查真实 UART/BLE/SPI/DSI 驱动符号存在；运行时硬件 I/O 仍禁用。
- 修复后构建静态占用：C3 Flash 688263 B、全局 RAM 24660 B；P4 Flash 387594 B、全局 RAM 30340 B。动态分配的帧缓冲/PSRAM 不在此 RAM 数值内，不能据此计算整机内存余量。
- 文档一致性、git diff --check 通过。没有运行 GitHub 远端 CI，也没有上传或烧录固件。
- 交付包另行解压到新目录，验证原生测试及两个目标独立编译。MANIFEST.json 的全部文件长度与 SHA256 由独立 Python 校验核对；打包工具自身不把这些验证标记为自动通过。

测试数据全为合成。串口和 BLE 驱动回归只替换硬件 API 边界，执行实际生产状态机代码；不证明真实 UART 缓冲、SPI 时序、BLE 手机兼容或屏幕扫描行为。

## 最终审查与修复

一名独立上下文审查者只读审查整个软件分支，提出 3 个 Important、0 个 Critical、0 个 Minor。3 个问题都先新增复现测试并观察失败，再修复并通过完整套件：

1. 超期 UART 尾字节刷新旧温度：先处理超时，调度器响应提交再次核对期限，剩余旧缓冲不能进入新事务。
2. 过期 BLE 半批次卡住发送：丢弃失效半批次，使用最新有效快照恢复三特征发送。
3. FR/RR 完整热图与八分区方向相反：按镜像标志同时映射像素及有效位，保留原始矩阵。

无待处理的 Minor。修复采用一次回归修复流程，没有用第二轮审查代替失败到通过的测试证据。

## 实施决策与代价

1. 只交付离线软件，保留实物关卡：符合用户当前条件；代价是尚不能证明整机可用或授权制造。
2. 缺核准 profile 时禁用全部硬件 I/O：未猜测接线；代价是实物调试前必须补充核准引脚、面板及辅助字段。
3. 原生测试使用本地隔离的官方 Zig 0.14.1：固件工具链不变；代价是其他电脑需自备 C++17 编译器，软件包不附编译器。
4. ROI 跟踪和低通系数依据真实时间间隔，跃变参考系数上限 0.45：适应较慢成品探头；代价是跟手性需热源实测调参。
5. 仅编译期配置，不做运行期 Flash 保存：避免宣称未实现的掉电保存；代价是运行期设置持久化需后续实现。
6. SPI 头 byte31 使用 bit1/bit2 表示 BLE 连接/启用：本地显示有状态来源；代价是新端点必须使用一致的 v1 布局。
7. SPI 固定 1728 字节全双工、流水响应与 token：避免变长阶段失步；代价是额外带宽和往返，100 ms 窗口需要实测。

## 审查中保留到硬件关卡的事项

每项均按“继续保留，尚未通过”处理：

| 事项 | 当前决定及原因 | 代价 |
| --- | --- | --- |
| 探头响应格式、内部冻结、帧内一致性、实际采样率 | 关卡 A，缺真实探头；接收相同图像不声称是新曝光 | 寄存器假设或驱动可能需修订 |
| 四 BLE 共存、辅助字段、手机失效显示 | 关卡 B/C，未接手机和四路实物；辅助字段未核准不启用 BLE | 手机协议或失效策略可能需修订 |
| SPI READY/ISR、建立保持、MISO 三态 | 关卡 D，缺实际波形；保留 CRC/token/期限保护 | 握手或时序可能需修订 |
| DSI 扫描、撕裂、FPS、可读性 | 关卡 D，无核准面板；保留双刷新租约 | 显示驱动与性能可能需调整 |
| 启动压降、断电、支路隔离、车载保护 | 关卡 E/F，无集成板和测量 | 电源或恢复设计可能需修改 |
| PCB、引脚、面板 profile 核准 | 不伪造制造文件，沿用编译期配置决定 | 制造前仍需可编辑 EDA 设计和核准 profile |

审查另排除了“必需 additional-urls”和“loop 只有 yield 必然触发看门狗”两个候选：本机默认官方索引含 core 3.3.7，所用 core 的单核 loopTask 有 yieldIfNecessary；这不代表远端 CI 或实物看门狗已经验证。

## 硬件交接

先以只读工具验证真实成品探头，再依次进行单轮/四轮 RaceChrono、SPI、核准 7 英寸面板、供电及车辆验证。前轮约 2 m、后轮约 4.5 m 线束必须进入台架测试。没有已验证 BOM、Gerber 或投板依据。

30 FPS 是目标，未测量；四幅 32×24 热图预览为合成数据。旧无线 v3、MAX31856 与 RS485 刹车固件未修改。
