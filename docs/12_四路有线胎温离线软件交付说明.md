# 六接口中控离线软件 0.2.0

这是离线研发版本，hardware_validated=false，实际帧率、手机及汽车电气未验证。

完整固件：`firmware/wired_tire_channel/wired_tire_channel.ino`（四块C3各一身份）、`firmware/wired_brake_channel/wired_brake_channel.ino`（第五C3管理双前刹车）、`firmware/wired_tire_display/wired_tire_display.ino`（微雪7B/P4）。共享库安装包WiredTireCore.zip及显示vendor驱动/许可证随包。

胎温FL/FR/RL/RR仍为四独立RejsaRubberTrac BLE身份、1FF7、三特征20字节、B4–19八个小端int16/10℃，不是 DIY CAN。本地四幅完整32×24；刹车独立N BrakeTemp/1FF8，0x100..107全部字节定义/单位/缩放/计算见13_六接口中控板间与刹车接口.md。Core/Fast/Dose为估算。

## 安装和离线验证

使用Arduino CLI1.5.0、ESP32 core3.3.7（IDF5.5.2），不安装latest。P4两芯片变体均PSRAM=enabled；新刹车必须CDCOnBoot=cdc，UART0/1用于探头，USB18/19留日志。Arduino IDE可打开三个完整ino文件并安装共享库ZIP；显示选择ESP32P4 Dev Module与实际chip variant，开启PSRAM。编译默认I/O禁用，编译成功不能直接接线烧录后使用。

```powershell
./scripts/test_wired_tire_core.ps1 -Case all -CompilerPath <C++17编译器或Zig路径>
python -m unittest discover -s tests/wired_tire -p 'test_*.py'
./scripts/compile_wired_tire.ps1 -Target channel
./scripts/compile_wired_tire.ps1 -Target brake
./scripts/compile_wired_tire.ps1 -Target display -ChipVariant prev3
./scripts/compile_wired_tire.ps1 -Target display -ChipVariant postv3
```

Windows若本机会阻止本地脚本，可在本次进程使用`powershell -NoProfile -ExecutionPolicy Bypass -File ...`，不改变系统策略。原生编译器可用环境变量WIRED_TIRE_CXX指定，构建产物只写本工作树workspace；若未找到编译器明确失败，不跳过测试。

# 四路有线胎温中控：离线软件包

范围说明：本文及 `0c29469` ZIP 对应原四轮胎温离线软件，不包含后续六接口（四胎温＋两前刹车）功能。最新设计见 `docs/superpowers/specs/2026-10-24-six-port-tire-brake-7b-design.md`；新增刹车子系统使用独立 DIY CAN BLE，不能把下文胎温 RejsaRubberTrac 描述当作整个新整机只使用一种协议。

这是离线研发版本，不是可直接上车的稳定固件。真实探头、RaceChrono、SPI 接线、面板、车载电源和赛道环境均需通过相应硬件关卡。

## 文件与安装

- firmware/wired_tire_channel/wired_tire_channel.ino：C3 单轮采集/BLE 单元，四份实例由未来核准的 profile 区分。
- firmware/wired_tire_display/wired_tire_display.ino：P4 四轮完整热图显示主控。
- WiredTireCore.zip：Arduino IDE 通过“添加 ZIP 库”安装；源代码也在 firmware/libraries/WiredTireCore。
- scripts/capture_yf90640.py：只读串口抓包工具，实际使用需要 pyserial 3.5 和已确认的端口/串口配置。
- tests/wired_tire：协议、滤波、调度、BLE 编码、SPI 快照、显示及工具测试。

Arduino-ESP32 基线 3.3.7。安装共享库后，Arduino IDE 分别选择 ESP32C3 Dev Module 与 ESP32P4 Dev Module，再打开对应完整 sketch。默认离线模式仅运行日志，不启用未核准硬件。

## CLI 验证

在软件包根目录执行：

~~~powershell
powershell -File scripts/compile_wired_tire.ps1 -Target channel
powershell -File scripts/compile_wired_tire.ps1 -Target display
powershell -File scripts/test_wired_tire_core.ps1 -Case all -CompilerPath <原生编译器完整路径>
python -m unittest discover -s tests/wired_tire -p 'test_*.py'
~~~

原生编译器支持 g++、clang++ 或 Zig 的 C++ 驱动。固件离线构建保留并检查完整硬件驱动链接路径，但运行时 I/O 仍关闭；编译成功不证明接线、时序、实物帧率或手机兼容。

## 上硬件之前

离线包不包含 ApprovedChannelProfile.h 或 ApprovedDisplayProfile.h。引脚、面板时序、DPHY 供电、厂商命令及 BLE 保留字段必须依据实物验证核准，再由独立硬件 profile 提供。不能把 -1 引脚、默认全零辅助字段或未核准的 PanelConfig 当作可用配置。

本地屏幕显示完整 32×24 热图，RaceChrono 使用八分区 RejsaRubberTrac 风格协议，不是 DIY CAN。屏幕界面以 30 FPS 为目标，成品探头真实新帧率独立验证；模拟预览不能作为帧率或实车证据。

详见 docs/11_四路有线胎温中控接口.md、设计规格和 hardware/wired_tire_central/notes/validation_matrix.md。

离线验证记录见 hardware/wired_tire_central/notes/validation_offline.md。测试所用串口/BLE 边界替身仅用于重放驱动状态机，不代表真实收发、射频或电气时序。

## 包完整性

MANIFEST.json 记录源提交、源目录是否有未提交内容、每个交付文件的 SHA256，以及 hardware_validated=false、actual_fps_measured=false。打包本身不执行验证；验证结果以随附记录和执行日志为准。清单不包含自身的哈希。

本包不包含制造 Gerber、已验证 BOM 或已实测接线，不应据此投板。后续硬件关卡通过后应生成新的版本和验证记录。
