# 四路有线胎温中控：7B 显示套件与采集底板设计变更

## 1. 用户已确定的要求

- 显示采用现成的 **微雪 ESP32-P4-WIFI6-Touch-LCD-7B**，使用其完整 7 英寸开发套件。
- **同一外壳：显示套件＋一块四接口采集底板**。屏幕使用套件原有主板连接；套件和采集底板分别固定在外壳内。
- 四个成品 RS485 MLX90640 探头接到采集底板的 FL/FR/RL/RR 四个插口；前轮约 2 m，后轮约 4.5 m。
- 本地显示四幅完整 **32×24 热图**；RaceChrono 保留四个独立轮位、各八分区的 RejsaRubberTrac 风格 BLE 输出。
- 无高度、无轮端电池；随车辆点火供电自动工作，点火电源关闭后系统关闭。

此前讨论的 5 英寸套件不作为本次方案。

## 2. 方案比较与选择

| 方案 | 取舍 | 本次结论 |
| --- | --- | --- |
| 自行设计 P4、屏幕接口和四路采集在同一块 PCB 上 | 集成度高，但承担显示主板、MIPI 供电与布线设计 | 原设计基线，本次被替换 |
| 7B 完整显示套件＋四接口采集底板，同一外壳 | 复用套件显示硬件；增加板间连接及机械固定核查 | **用户已选择** |
| 5 英寸显示开发套件 | 尺寸更小，需要重新核对型号、分辨率与布局 | 用户最新选择为 7B，不采用 |

本次采用套件的原因是复用现成显示硬件，同时保留独立、可维护的四路接口和既有数据路径。

## 3. 硬件与软件分工

| 部件 | 职责 |
| --- | --- |
| 7B 套件上的 ESP32-P4 与原配屏幕 | SPI 主机，接收四轮完整快照，绘制四区热图及采集/BLE 状态 |
| 采集底板上的四个 ESP32-C3 单元 | 每轮独立 RS485 采集、八分区计算、单轮 BLE、SPI 快照交付 |
| 底板四路 RS485 与四个插口 | 独立接入四探头，包括经审查的收发、接地参考与线路保护 |
| 底板电源与支路保护 | 车载入口保护、探头支路保护、采集逻辑及显示套件匹配电源 |
| 外壳及板间线束 | 两部分独立固定、接口应力释放、短连接、维护可达性和天线净空 |

底板保留四个 C3，不通过套件自带的单个 C6 直接替代四个 BLE 身份。由实施者默认关闭不需要的套件无线/音频/摄像头功能，这是本设计的工程取舍：首版只需显示与采集，减少资源占用及额外射频活动。RTC、USB 维护等底层板级依赖按 BSP 要求保留。

显示主控重启、界面繁忙或屏幕失效时，各轮采集与 BLE 不依赖显示任务继续运行；整机电源故障的隔离能力仍需真实电路及台架验证。

## 4. 套件依据与待核准事项

[微雪官方 7B 文档](https://docs.waveshare.com/ESP32-P4-WIFI6-Touch-LCD-7B)列出：7 英寸横屏 1024×600、MIPI-DSI、P4 与 C6、32 MB PSRAM 和扩展 GPIO。扩展接口为 PH2.0 两组 12 针接口，不能套用此前 5 英寸板的 40 针定义。

分辨率与离线界面一致，可以复用四区布局、逐像素温度和有效位、镜像、共享色标及失效显示逻辑；这不代表通用 PanelDriver 能直接驱动 7B。

适配前由实施者取得并记录：实际 PCB/芯片修订版、面板及触摸控制器、匹配的官方原理图与机械图、面板命令、背光/复位及供电路径、实际可用 GPIO 与板载外设占用、官方 BSP/示例提交和依赖。先运行匹配的板级检查及显示原型，再冻结应用 profile。

[官方资源页](https://docs.waveshare.com/ESP32-P4-WIFI6-Touch-LCD-7B/Resources-And-Documents)与[官方示例仓库](https://github.com/waveshareteam/ESP32-P4-WIFI6-Touch-LCD-7B)为实现输入。现有离线编译基线仍为 Arduino-ESP32 3.3.7，不能将其编译通过当作任意批次 7B 的兼容认证。若需要调整显示侧依赖，须在计划中说明范围并隔离构建环境，不自动升级 C3 或旧固件。

本文不冻结 GPIO 号、连接器接线、供电电流、BOM 或外壳尺寸；这些交由实施者依据资料和实物核准。不能依据接口名称或空闲数量直接给出施工接线。

## 5. 板间通信

沿用 SPI 快照 v1：1 MHz、mode 0、固定 1728 字节全双工、四片选、四 READY、CRC/token 校验和异步 DMA。

现有主机接口需要 3 根总线信号＋4 CS＋4 READY，共 11 个 GPIO，另有信号地及必要供电。实施者完成资源表及新旧对照；原显示侧引脚均为未核准占位 `-1`，没有可沿用的真实接线，本次不修改固件引脚。

这是同一外壳内的短距离板间连接，不延伸到轮眉；2 m/4.5 m 轮眉线束继续使用 RS485。板间线缆、接地与屏蔽、MISO 三态、复位时反灌、READY 时序及建立保持时间均需台架核对。若不能分配 11 个合适 GPIO，实施者先提出桥接/接口修订并重新审阅，不静默合并轮位或减少热图内容。

DMA 完成前不覆写发送缓冲；重读旧快照不刷新有效期；年龄继续采用从机年龄＋请求耗时＋接收后本地经过时间。保留 1500 ms 过期基线，不将传输成功声称为新测温曝光。

## 6. 显示、RaceChrono 与供电

沿用 FL/FR/RL/RR 四区、各完整 768 点热图、最高有效温度、采集/BLE 状态与数据年龄；四轮共用色标，FR/RR 镜像与八分区一致。界面目标仍为 30 FPS，测温新帧率另行记录，没有真实测量前不宣称已达到。

RaceChrono 名称格式、轮位、服务 `0x1FF7`、特征 `0x0001/0x0002/0x0003`、每特征 20 字节沿用；B0=`0x02`，B4–B19 为八个小端 int16 温度计数，摄氏度＝计数/10。B1–B3 高度/电池辅助字段仍需实测核准，不把占位值当作真实测量。这不是 DIY CAN，不新增 PID。

供电随点火控制：车载入口保险/限流、反接与瞬态保护，经审查的稳压分别匹配采集逻辑和 7B 供电入口，探头采用独立受保护支路。套件不被当作已有车载输入保护的部件，输入电压、峰值电流、连接器及回流由原理图和测量确定。

不安装整机续航电池。套件电源开关保持在核准工作位置，验证供电恢复后无需按键即可进入采集/显示，以及关点火后实际关闭；USB 调试供电可能造成旁路，验收记录是否接 USB。启动压降、短暂掉电和快速重新上电需复测，不依赖关机瞬间写 Flash。

## 7. 机械与验证顺序

同一个外壳内，显示套件和采集底板分别为独立 PCB；底板不自行重画 P4、C6、DSI 高速线路与屏幕专用电源。实施者依据机械图决定底板在套件后方或相邻位置，核查四个 C3 天线与屏幕金属背板净空、散热、固定点、锁止及线束应力释放。

验证沿用 A–F：单探头只读抓包 → 单轮 BLE → 四轮共存 → 7B 独立显示原型及板间 SPI → 四路显示/BLE 同时运行 → 电源线束和整机 → 车辆。7B 资料核对及独立显示原型可提前进行；正式底板投板仍消费探头、BLE、GPIO/SPI、显示和电源预算证据。

保留正常温度与无效状态分离、超期 UART 响应拒绝、BLE 半批次恢复、镜像与 DMA 租约等已修复行为。旧无线 v3 和刹车固件不在本次改动范围。
