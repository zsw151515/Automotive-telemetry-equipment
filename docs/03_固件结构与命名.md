# 03 固件结构与命名

## 四路有线胎温中控的新目录

- `firmware/wired_tire_channel/wired_tire_channel.ino`：ESP32-C3 单轮采集/BLE，完整 sketch 与本地硬件适配文件。
- `firmware/wired_tire_display/wired_tire_display.ino`：ESP32-P4 显示主控，不能按 C3 目标编译。
- `firmware/libraries/WiredTireCore`：两份固件共用的可移植核心，Arduino IDE 安装共享库 ZIP，CLI 使用 `--libraries firmware/libraries`。

使用 `scripts/compile_wired_tire.ps1 -Target channel` 或 `-Target display` 分别构建，默认离线且关闭 I/O。完整交付按 `docs/12_四路有线胎温离线软件交付说明.md` 操作。

## 1. 固件目录建议

建议统一使用如下目录：

```text
firmware/
├─ tire_temp_height_node_v2/
│  └─ tire_temp_height_node_v2.ino
├─ tire_temp_height_node_v3/
│  └─ tire_temp_height_node_v3.ino
├─ tire_temp_height_node_v3_ble_only/
│  └─ tire_temp_height_node_v3_ble_only.ino
├─ central_display_tft/
│  └─ central_display_tft.ino
├─ brake_temp_12v_max31856/
│  └─ brake_temp_12v_max31856.ino
└─ brake_temp_alarm_display/
   └─ brake_temp_alarm_display.ino
```

## 2. 文件命名原则

文件名应包含：

- 功能
- 硬件版本
- 传感器或通信方式
- 是否为稳定版

示例：

```text
tire_temp_height_node_v3_rejsa_ble_stable.ino
brake_temp_12v_max31856_racechrono.ino
central_tft_espnow_touch_ack.ino
brake_temp_alarm_display_rs485_oled.ino
```

## 3. 代码顶部信息模板

每个 `.ino` 文件顶部建议写：

```cpp
// =====================================================
// 项目：汽车赛道遥测设备
// 固件：胎温高度节点 v3
// 硬件：ESP32-C3 + MLX90640 + VL53L1X + LTC2954-2
// 通信：RaceChrono BLE / ESP-NOW
// 版本：stable_xxx
// 说明：优先保证稳定性，不要随意修改引脚和 BLE 协议
// =====================================================
```

## 4. 推荐代码结构

```cpp
#include ...

// 1. 项目信息
// 2. 用户配置
// 3. 引脚定义
// 4. 常量参数
// 5. 全局状态
// 6. 传感器对象
// 7. BLE / ESP-NOW 对象
// 8. 工具函数
// 9. 传感器初始化
// 10. 通信初始化
// 11. 按键处理
// 12. 显示 / 报警处理
// 13. setup()
// 14. loop()
```

## 5. 引脚定义规则

所有引脚必须集中放在文件前部，例如：

```cpp
const int SDA_PIN = 8;
const int SCL_PIN = 10;
const int LED_STAT_PIN = 2;
```

不要在代码中间散落魔法数字。

不推荐：

```cpp
digitalWrite(2, LOW);
```

推荐：

```cpp
digitalWrite(LED_STAT_PIN, LOW);
```

## 6. 用户参数规则

报警温度、轮位 ID、BLE 名称、滤波系数等应集中定义：

```cpp
const uint8_t TIRE_ID = 3;
const char* DEVICE_NAME = "RejsaRubberRL123456";
float alarmTempC = 600.0f;
```

## 7. 传感器异常处理

所有传感器读取都要处理失败：

- I2C 初始化失败
- SPI fault
- NaN
- inf
- 超出物理范围
- 连续失败

不要直接把异常变成 0，除非界面明确显示为故障状态。

## 8. RaceChrono 相关命名

RaceChrono BLE 代码建议保留清晰注释：

- 设备名
- Service UUID
- Characteristic UUID
- 数据包格式
- 轮位 ID
- 发送频率

不要让 Codex 在不知道协议的情况下重命名这些内容。

## 9. 版本管理建议

当某个固件已经实车稳定，应在文件或 README 里标记：

```text
状态：实车稳定 / 台架稳定 / 开发中 / 已废弃
```

不要删除旧稳定版，建议保留：

```text
archive/
```

或用 Git tag 管理。

## 10. 修改说明模板

每次修改代码建议在回复或 PR 中说明：

```text
修改内容：
- xxx
- xxx

保留行为：
- RaceChrono BLE 未修改
- 引脚定义未修改
- 传感器初始化流程未修改

测试步骤：
1. 编译
2. 烧录
3. 串口查看启动日志
4. RaceChrono 搜索设备
5. 传感器热源测试
```
