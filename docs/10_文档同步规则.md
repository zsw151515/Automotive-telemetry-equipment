# 10 文档同步规则

本文件用于约束 Codex / ChatGPT 在后续项目演进过程中，如何同步维护 README、CODEX、docs、firmware 和 hardware 目录说明。

核心原则：

> 代码、硬件、通信协议、目录结构、测试流程或已知问题发生变化时，必须检查是否需要同步更新文档。

文档不是可有可无的附属文件，而是 Codex 正确理解本项目边界、防止改错版本、防止混淆硬件方案的重要依据。

---

## 1. 每次任务完成后必须检查文档

Codex 每次完成以下任意类型任务后，都必须检查是否需要同步更新文档：

- 修改固件代码
- 修改硬件设计
- 新增目录
- 删除目录
- 重命名文件或目录
- 改变硬件版本边界
- 改变传感器型号
- 改变通信方式
- 改变 RaceChrono BLE 行为
- 修改 BLE DIY CAN 自定义通道相关固件，即使 PID 没有变化
- 改变 RS485 / Modbus 协议
- 改变引脚定义
- 改变按键逻辑
- 改变蜂鸣器报警逻辑
- 改变显示 UI
- 改变电源控制逻辑
- 发现新的已知问题
- 修复一个重要硬件坑
- 新增测试流程或交付流程

如果不需要更新文档，必须在最终回复中说明：

```text
本次不需要更新文档，原因是：xxx
```

---

## 2. 需要优先检查的文档

每次修改后，至少检查以下文件是否需要同步：

```text
README.md
CODEX.md
AGENTS.md
docs/*.md
firmware/对应目录/README.md
hardware/对应目录/README.md
```

不要只改代码，不检查文档。

不要只改一个 README，而忘记 CODEX 或 docs。

---

## 3. 什么时候必须更新 README.md

以下变化必须考虑更新根目录 `README.md`：

- 当前主线版本变化
- 新增或废弃一个硬件版本
- 新增或废弃一个固件版本
- 仓库目录结构变化
- 某个版本从“测试版”变为“当前主线”
- 某个版本从“当前主线”变为“历史参考”
- 项目最高优先级变化
- RaceChrono / RS485 / BLE / ESP-NOW 等通信架构发生变化
- BLE DIY CAN 自定义通道的 PID、通道、字节布局、缩放倍率、无效值或 RaceChrono 计算公式发生变化

示例：

```text
胎温高度 v3 从 ESP-NOW + 中控改为 RaceChrono BLE only
```

这种变化必须更新 README.md。

---

## 4. 什么时候必须更新 CODEX.md

以下变化必须考虑更新 `CODEX.md`：

- 新增 Codex 必须遵守的规则
- 发现 Codex 容易混淆的版本边界
- 某个版本的“严禁事项”变化
- 固件修改原则变化
- 引脚定义变化
- RaceChrono BLE 协议、设备名、UUID、通道布局变化
- BLE DIY CAN 自定义通道的 PID / CAN ID、payload 字节布局、单位、缩放倍率、无效值或 RaceChrono 计算公式变化
- RS485 Modbus 参数变化
- 电源控制硬件结论变化
- 项目主线变化

`CODEX.md` 是 Codex 读仓库时最重要的规则文件。

如果一个规则是为了防止 Codex 改错，就应该写进 `CODEX.md`。

---

## 5. 什么时候必须更新 docs 文件

`docs/` 用于写更详细的专项说明。

建议对应关系：

```text
docs/02_硬件版本说明.md
= 硬件版本、历史版本、主线版本边界

docs/05_已知硬件问题与排查记录.md
= 硬件坑、故障排查、实测修复结论

docs/08_12V_RS485刹车节点说明.md
= brake_temp_12v_rs485 / brake_temp_alarm_display_12v_rs485 相关规则

docs/09_胎温高度v3_RaceChrono_BLE_ONLY说明.md
= 胎温高度 v3 RaceChrono BLE only 固件规则

docs/10_文档同步规则.md
= 文档同步维护规则
```

如果新增了一个大方向，例如新的 GPS 节点、新的刹车节点、新的中控屏幕，可以新建新的 docs 文件，而不是把所有内容塞进 README。

---

## 6. 什么时候必须更新 firmware 目录 README

如果改动影响某个固件目录，必须检查该目录下的 README。

例如：

```text
firmware/tire_temp_height_node_v3/README.md
```

需要更新的情况：

- 固件功能变化
- 通信方式变化
- 依赖库变化
- 引脚定义变化
- BLE 设备名变化
- RaceChrono 通道变化
- BLE DIY CAN 自定义通道的 PID、payload、缩放倍率、无效值或 RaceChrono 计算公式变化
- 传感器读取逻辑变化
- 按键逻辑变化
- 报警逻辑变化
- 测试状态变化
- 从“待上传”变为“已验证稳定”

---

## 7. 什么时候必须更新 hardware 目录 README

如果改动影响某个硬件目录，必须检查该目录下的 README。

例如：

```text
hardware/tire_temp_height_v3/README.md
hardware/brake_temp_12v_max31856/README.md
hardware/brake_temp_12v_rs485/README.md
hardware/brake_temp_alarm_display_12v_rs485/README.md
```

需要更新的情况：

- 原理图变化
- PCB 版本变化
- BOM 变化
- 器件型号变化
- 引脚连接变化
- 电源方案变化
- 接口定义变化
- 外壳 / 安装方式变化
- 已知硬件问题变化
- 实测修复结论变化
- 某个硬件从测试版变为主线

---

## 8. 当前项目版本边界必须保持一致

以下边界必须在所有文档中保持一致。

### 8.1 胎温高度节点 v3

```text
胎温高度节点 v3
= RaceChrono / RejsaRubberTrac BLE only
= 不再向中控发送胎温数据
= 不再使用 ESP-NOW / WiFi / UDP / TCP 胎温主链路
= 最高优先级是 RaceChrono 数据准确、热力分布跟手、温度不过度抖动
```

如果有任何文档还写着“v3 继续向中控发送胎温数据”，必须修正。

### 8.2 brake_temp_12v_max31856

```text
brake_temp_12v_max31856
= MAX31856 + K 型热电偶
= 测卡钳温度
= 当前未接入报警显示
= 独立采集 / 测试版本
```

不要写成刹车盘温度。

不要混入 RS485 红外传感器逻辑。

### 8.3 brake_temp_12v_rs485

```text
brake_temp_12v_rs485
= RS485 红外测温传感器
= 测刹车盘温度
= 不带显示报警
= brake_temp_alarm_display_12V_RS485 的初代版本
= 不作为当前重点推进对象
```

不要写成当前重点版本。

不要混入 ALM / 按键 / 蜂鸣器显示逻辑。

### 8.4 brake_temp_alarm_display_12v_rs485

```text
brake_temp_alarm_display_12v_rs485
= RS485 红外测温传感器
= 测刹车盘温度
= 带显示、ALM、按键、蜂鸣器、RaceChrono BLE
= 当前刹车节点板重点推进版本
```

不要写成 MAX31856 热电偶版本。

不要写成不带显示报警的初代版本。

## 9. 文档同步检查清单

每次提交前，Codex 应检查：

```text
[ ] 是否改动了当前主线定义？
[ ] 是否改动了目录结构？
[ ] 是否改动了固件功能？
[ ] 是否改动了硬件版本边界？
[ ] 是否改动了 RaceChrono 行为？
[ ] 是否涉及 BLE DIY CAN 自定义通道固件？如涉及，是否列出 PID / CAN ID、payload、单位、缩放倍率、无效值和 RaceChrono 计算公式？
[ ] 如果涉及胎温高度 v3，是否确认它是 RejsaRubberTrac 风格 BLE 热图，不是 DIY CAN PID 方案？
[ ] 是否改动了 RS485 / Modbus 参数？
[ ] 是否改动了引脚定义？
[ ] 是否改动了按键 / 蜂鸣器 / 显示逻辑？
[ ] 是否新增了已知问题或修复结论？
[ ] 是否需要更新 README.md？
[ ] 是否需要更新 CODEX.md？
[ ] 是否需要更新 docs/*.md？
[ ] 是否需要更新 firmware/*/README.md？
[ ] 是否需要更新 hardware/*/README.md？
```

---

## 10. Codex 最终回复必须包含文档同步结果

Codex 完成任务后，最终回复必须包含：

```text
代码文件修改：
- xxx

文档文件修改：
- xxx

未修改文档及原因：
- xxx：原因 xxx

需要用户实测确认：
- xxx
```

如果没有修改代码，只修改文档，也要说明。

如果没有修改文档，也要说明为什么。

如果本次涉及 BLE DIY CAN 自定义通道固件改动，最终回复必须额外包含：

```text
BLE DIY CAN PID 与公式：
- PID 0xXXX / 通道名 / payload / 类型 / 单位 / 缩放 / 无效值 / RaceChrono 公式
```

即使 PID 没有变化，也要列出当前固件实际发送的 PID 和公式。

胎温高度 v3 的 RejsaRubberTrac 风格 BLE 热图不适用上述 PID / 公式要求；修改该版本时应说明设备名、Service、Characteristic、轮位 ID、数据包布局和 RaceChrono 热图行为。

## 11. 推荐给 Codex 的固定提示词

以后可以在 Codex Windows 应用里复制以下内容作为任务附加要求：

```text
本次任务完成后，请检查是否需要同步更新项目说明文档。

如果本次修改涉及：
- 项目主线变化
- 固件功能变化
- 通信方式变化
- RaceChrono 行为变化
- 硬件版本边界变化
- 引脚定义变化
- 报警逻辑变化
- 测试流程变化
- 已知问题变化
- 目录结构变化

请同步更新：
1. README.md
2. CODEX.md
3. 对应 docs/*.md
4. 对应 firmware/*/README.md
5. 对应 hardware/*/README.md

如果你判断不需要更新文档，请在最终回复中明确说明“不需要更新文档”的原因。
```

---

## 12. 不允许的行为

除非用户明确要求，否则 Codex 不允许：

- 只改代码但不检查文档
- 只改 README 但不检查 CODEX
- 只改 docs 但不检查 firmware / hardware 目录 README
- 把历史测试板写成当前主线
- 把独立版本写成当前重点版本
- 把三个刹车版本混成一个版本
- 把胎温高度 v3 写回需要中控胎温发送
- 删除重要已知问题记录
- 删除已经实测验证的重要硬件结论
