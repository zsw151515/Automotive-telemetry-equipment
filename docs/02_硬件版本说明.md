# 02 硬件版本说明

## 独立研发方向：四路有线胎温中控

2026-10-24 用户最新选择为微雪 7B 完整显示套件＋六接口采集底板、同一外壳：四个成品 RS485 MLX90640 胎温探头及两前刹车盘温度探头。工程基线为四个胎温 C3 加一个双路刹车 C3，保留四幅完整热图/各轮八分区及刹车 N BrakeTemp DIY CAN。刹车报警功能并入底板，触屏替代小屏/设置按键，保留蜂鸣。无高度、无轮端电池，随点火供电。详见 `docs/superpowers/specs/2026-10-24-six-port-tire-brake-7b-design.md`；原四口和定制 P4 同板结构为历史，适配仍待完成。

当前仅实施离线软件，未完成实物验证或投板；该方向不改变下面既有硬件版本定位。规格和验证矩阵见 `docs/superpowers/specs/2026-10-22-wired-tire-thermal-central-design.md` 与 `hardware/wired_tire_central/notes/validation_matrix.md`。

## 1. 胎温高度节点 v2（历史测试板）

胎温高度节点 v2 是较早的验证版本，仅作为历史测试板和参考资料保留。

v2 曾用于验证：

- MLX90640 胎温读取
- VL53L1X 高度读取
- RaceChrono BLE 输出
- 早期 ESP-NOW 到中控显示
- 电池电压检测
- 基础按键 / LED 状态

### 1.1 主要硬件

- MCU：ESP32-C3 模块 / 开发板形态
- 胎温传感器：MLX90640
- 高度传感器：VL53L1X
- 供电：锂电池 + 3.3V LDO
- 通信：BLE + 早期 ESP-NOW
- USB：Type-C

### 1.2 当前定位

```text
状态：历史测试板 / 参考资料
是否当前主线：否
```

v2 可作为历史对照，但不建议作为新功能主线继续扩展。

## 2. 胎温高度节点 v3（当前主线）

v3 是当前更接近产品化的版本，重点加入单按键电源控制、Type-C 优化、更多测试点和更明确的电源路径。

### 2.1 主要硬件

- MCU：ESP32-C3
- 胎温传感器：MLX90640
- 高度传感器：VL53L1X
- 电源控制：LTC2954
- 电池充电：TP4057
- 3.3V LDO：ME6211C33M5G-N
- USB ESD：USBLC6-2SC6
- P-MOS：AO3407A
- Type-C 接口

### 2.2 当前通信定位

胎温高度节点 v3 当前主线已经改为：

```text
RaceChrono / RejsaRubberTrac compatible BLE only
```

也就是说：

```text
MLX90640 胎温 + VL53L1X 高度
        ↓
本地清洗 / 滤波 / ROI / 分区
        ↓
BLE RejsaRubberTrac 风格数据包
        ↓
RaceChrono Pro
```

当前 v3 不再向中控发送胎温数据。

不再使用：

```text
ESP-NOW -> 中控胎温
WiFi -> 中控
UDP/TCP -> RaceChrono
Central display link
```

### 2.3 v3 关键修复结论

当前已经通过实测确认：

- 应使用 `LTC2954CTS8-2#TRPBF`
- `R_BTN_PULL` 应 DNP / 删除
- `PWR_KILL -> SYS_3V3` 增加 47kΩ 上拉
- 该方案在电池供电下连续约 30 次开机测试稳定

### 2.4 典型引脚

```cpp
const int SDA_PIN          = 8;
const int SCL_PIN          = 10;
const int VBAT_ADC_PIN     = 1;
const int LED_STAT_PIN     = 2;  // 低电平点亮
const int BTN_PIN          = 3;  // 低电平有效
const int PWR_KILL_PIN     = 4;  // HIGH 保持电源
const int PWR_INT_PIN      = 5;
const int VL53_XSHUT_PIN   = 6;
const int VL53_INT_PIN     = 7;
```

### 2.5 v3 修改注意事项

不要轻易修改：

- `PWR_KILL_PIN`
- `PWR_INT_PIN`
- `BTN_PIN`
- `VL53_XSHUT_PIN`
- `VL53_INT_PIN`
- RaceChrono BLE 相关逻辑
- MLX90640 温度清洗 / 滤波 / ROI / spike gate / fallback 逻辑

v3 的电源控制是历史上出过严重问题的部分，所有相关修改必须保守。

v3 的软件主线是 RaceChrono 数据质量，所有功能扩展都不能影响：

```text
RaceChrono 数据准确
热力分布跟手
温度不过度抖动
BLE 连接稳定
```

## 3. brake_temp_12v_max31856（独立卡钳热电偶版本）

该版本是独立的 12V MAX31856 + K 型热电偶采集版本。

### 3.1 定位

```text
测量目标：卡钳温度
当前状态：独立采集 / 测试版本
是否当前报警显示主线：否
是否已接入报警显示：否
```

### 3.2 主要硬件

- MCU：ESP32 / ESP32-C3，视具体板子而定
- 温度芯片：MAX31856
- 传感器：K 型热电偶
- 供电：汽车 12V -> 降压 -> 3.3V

### 3.3 重点风险

- 热电偶线较长，容易引入干扰
- 刹车附近高温和震动强
- 车载 12V 电源有浪涌和噪声
- MAX31856 前端需要合理滤波和接地
- 仅 12V 供电时出现过热源接触导致数据卡住 / 归 0 的问题

### 3.4 软件处理原则

- 保留 MAX31856 fault 读取和日志
- 不要把 fault 简单隐藏
- 异常值要滤波，但不能误导用户
- 不要把卡钳温度误写成刹车盘温度
- 当前未接入报警显示，除非用户明确要求，不要擅自加入报警显示架构

## 4. brake_temp_alarm_display_12V_RS485（当前刹车盘报警显示主线）

该版本使用 RS485 红外测温传感器，测量刹车盘温度。

### 4.1 定位

```text
测量目标：刹车盘温度
传感器类型：RS485 红外测温传感器
功能：显示 + 报警 + RaceChrono BLE 数据发送
是否当前主线：是
```

### 4.2 主要硬件

- RS485 红外测温传感器
- ESP32 / ESP32-C3 显示控制器
- OLED / TFT 显示屏
- SET / UP / DOWN 按键
- 蜂鸣器
- 12V / 5V 供电，视具体硬件而定

### 4.3 RS485 传感器参数

当前红外测温传感器手册要点：

```text
RS485 Modbus RTU
默认地址：0x01
默认波特率：9600
格式：8N1
读取功能码：0x03
温度寄存器：0x0000
返回值 / 10 = 摄氏度
```

### 4.4 软件处理原则

- 不要把本版本当成 MAX31856 热电偶版本
- 不要把刹车盘温度误写成卡钳温度
- RS485 失败、CRC 错误、温度无效不能显示或发送为正常 0°C
- OLED / 按键 / 蜂鸣器不能阻塞 RaceChrono BLE
- 必须保留 RaceChrono BLE 数据发送能力，除非用户明确要求移除
