# 08 12V RS485 刹车节点说明

本文件专门记录 **12V 供电 + MAX31856 + K 型热电偶 + RS485 通信 + RaceChrono BLE 输出** 的刹车温度节点方案。

重要结论：

> 12V RS485 刹车节点版本不仅要通过 RS485 发给本地报警显示中控，也需要向 RaceChrono Pro 发送刹车温度数据。

因此这个版本是 **RS485 + RaceChrono BLE 双输出架构**，不是单纯 RS485 本地显示版本。

Codex 修改代码时必须先确认当前目标是：

1. 12V MAX31856 刹车温度采集节点
2. RS485 报警显示中控
3. 还是采集节点 + 显示中控 + RaceChrono BLE 一体化版本

不要把 RS485 显示逻辑、MAX31856 采集逻辑和 RaceChrono BLE 发送逻辑互相覆盖掉。

---

## 1. 系统定位

12V RS485 刹车节点用于真实赛道环境下监测刹车盘 / 卡钳附近温度。

核心目标：

- 使用汽车 12V 供电
- 通过 MAX31856 读取 K 型热电偶
- 通过 RS485 向中控显示发送温度
- 通过 BLE 向 RaceChrono Pro 发送刹车温度数据
- 中控显示当前刹车温度和报警阈值
- 温度超过阈值时蜂鸣器报警
- 在强震动、高温、车载电源噪声环境下稳定运行

此版本优先级：

```text
稳定读取 > RaceChrono 稳定记录 > RS485 稳定显示 > 报警可靠 > 功能丰富
```

---

## 2. 推荐系统架构

推荐拆分为两个设备，也可以根据硬件版本做成一体式。

### 2.1 刹车温度采集节点

位置：靠近刹车 / 轮拱 / 传感器安装区域。

主要功能：

- 12V 输入
- 降压到 3.3V / 5V，视硬件而定
- MAX31856 读取 K 型热电偶
- 通过 RS485 发送温度到车内显示中控
- 通过 BLE 向 RaceChrono Pro 发送温度数据
- 可选本地状态 LED

主要器件：

- ESP32 / ESP32-C3
- MAX31856
- K 型热电偶
- RS485 收发器，例如 MAX3485 / SP3485 / MAX485 类器件
- 12V 降压电源模块 / 板载 Buck
- TVS / 保险丝 / 输入滤波，视硬件版本而定

### 2.2 RS485 报警显示中控

位置：车内驾驶员可视位置。

主要功能：

- 通过 RS485 读取一个或多个刹车温度节点
- 显示当前温度
- 显示报警阈值 `ALM`
- 按键设置报警阈值
- 控制蜂鸣器报警
- 传感器失败时显示 FAIL 或明确故障状态

常见显示：

- 1.3 寸 OLED
- ESP32 TFT
- 其他串口屏 / 小屏

### 2.3 RaceChrono BLE 输出

RaceChrono BLE 输出通常应在采集节点侧完成，因为采集节点最接近原始温度数据。

推荐逻辑：

```text
MAX31856 读取温度
        ↓
异常判断 / fault 判断 / 滤波
        ↓
同时输出：
  1. RS485 -> 中控显示 / 报警
  2. BLE   -> RaceChrono Pro 记录
```

不建议让显示中控再转发 RaceChrono，除非硬件和软件明确设计为“中控统一转发”。原因是中控转发会增加链路复杂度和延迟，并且 RS485 断线时 RaceChrono 也会失去数据。

## 3. 典型地址规划

当前项目中曾使用过如下地址概念：

```text
FL addr = 0x01
FR addr = 0x02
```

也可以扩展为四轮：

```text
FL = 0x01
FR = 0x02
RL = 0x03
RR = 0x04
```

如果只做单节点大字体显示，可以只读取一个地址，例如：

```text
BRAKE_NODE_ADDR = 0x01
```

Codex 修改 RS485 代码时，不要随意更改地址映射。若必须更改，必须在说明中列出新旧地址对应关系。

## 4. RaceChrono 通道规划

12V RS485 刹车温度版本必须支持 RaceChrono 数据输出。

### 4.1 推荐输出内容

最低要求：

```text
BrakeTemp = 当前刹车温度，单位 °C
```

如果双前轮刹车温度：

```text
BrakeTempFL
BrakeTempFR
BrakeTempMax
```

如果四轮刹车温度：

```text
BrakeTempFL
BrakeTempFR
BrakeTempRL
BrakeTempRR
BrakeTempMax
```

### 4.2 BLE 方案选择

刹车温度不像胎温热图那样必须走 RejsaRubberTrac 热图逻辑。

可选方案：

1. **RaceChrono BLE DIY CAN 风格通道**
   - 适合发送刹车温度这类自定义数值
   - 需要确认 iOS RaceChrono 的通道显示和命名限制

2. **复用已有项目 BLE 框架**
   - 如果当前固件已有 RaceChrono 可识别 BLE 代码，优先保留
   - 不要为了 RS485 显示把 BLE 删除

3. **不推荐单纯 UDP/TCP**
   - iOS RaceChrono 外部遥测限制较多
   - 本项目优先 BLE 稳定性

### 4.3 修改 BLE 代码注意事项

不要随意修改：

- BLE 设备名
- Service UUID
- Characteristic UUID
- 数据包格式
- RaceChrono 可识别的通道 ID / PID / CAN ID
- 发送频率

如果当前固件 RaceChrono 搜索不到设备，首先确认这份固件是否包含 BLE 广播逻辑，而不是只包含 RS485 显示逻辑。

## 5. RS485 通信方式说明

RS485 是物理层，不等于协议本身。

本项目 RS485 版本可能采用两种方式之一：

### 5.1 简单自定义串口协议

例如节点周期发送：

```text
ADDR,TEMP,STATUS\n
```

或中控轮询：

```text
REQ,01\n
```

节点回复：

```text
01,325.4,OK\n
```

优点：

- 代码简单
- 调试方便
- 串口工具可直接看

缺点：

- 抗干扰和错误校验需要自己做
- 多节点时需要处理冲突

### 5.2 Modbus RTU 风格

如果使用 Modbus RTU，应明确：

- 从机地址
- 波特率
- 校验位
- 寄存器地址
- 温度缩放比例
- CRC 校验

优点：

- 更标准
- 多节点更清晰
- CRC 校验可靠

缺点：

- 代码复杂度更高
- 调试门槛略高

### 5.3 当前建议

项目早期和单车调试阶段，推荐优先使用：

```text
简单轮询 + 明确地址 + 超时 + CRC 或 checksum
```

不要一开始就引入过度复杂协议。

## 6. 双输出时序建议

采集节点同时承担 MAX31856、RS485、BLE 时，必须避免互相阻塞。

推荐节奏：

```text
MAX31856 读取：5~20Hz，按实际稳定性调整
RS485 输出/响应：5~10Hz 或按中控轮询
RaceChrono BLE 发送：5~10Hz，优先稳定
OLED/TFT 刷新：5~10Hz，不要阻塞通信
按键扫描：20~50ms 级别
```

不要使用长时间 `delay()`。

推荐状态机：

```text
读取传感器任务
RS485 任务
BLE RaceChrono 任务
显示任务
按键任务
蜂鸣器任务
```

每个任务用 `millis()` 调度。

## 7. RS485 物理层设计注意事项

### 7.1 A/B 线

必须确保：

- A/B 不接反
- GND 参考线可靠
- 线束固定牢固
- 接插件抗震

很多 RS485 模块对 A/B 标注可能和其他厂家相反，现场调试时如果完全无响应，应尝试交换 A/B。

### 7.2 终端电阻

如果线较长或环境噪声大，建议总线两端加 120Ω 终端电阻。

但如果线很短、只有一个节点，终端电阻可根据实测决定。

不要在每个节点都加 120Ω，否则总线负载会过重。

### 7.3 偏置电阻

总线空闲状态需要稳定电平。

建议在主机端或总线一端考虑：

- A 上拉
- B 下拉
- 或使用带 fail-safe 的 RS485 收发器

### 7.4 GND 参考

车载环境下只接 A/B 有时不稳定，建议 RS485 线束同时带 GND 参考线。

典型线束：

```text
12V
GND
RS485_A
RS485_B
```

如果采集节点独立取电，也建议至少保证 RS485 GND 参考合理。

## 8. 12V 供电注意事项

车载 12V 并不是干净的 12V。

可能存在：

- 启动瞬态
- 发电机噪声
- 继电器 / 电机干扰
- 地电位差
- 刹车区域附近强干扰

建议硬件上考虑：

- 输入保险丝或自恢复保险丝
- 反接保护
- TVS 管
- LC / RC 输入滤波
- Buck 输入输出电容足够靠近芯片
- 3.3V 给 MAX31856 单独做好去耦

软件上必须考虑：

- 上电延时
- 传感器初始化失败重试
- RS485 通信超时
- BLE 断开后继续广播
- 异常值过滤
- 不因单次失败卡死

## 9. MAX31856 与 K 型热电偶注意事项

### 9.1 MAX31856 重点状态

代码应读取并打印：

- 热电偶温度
- 冷端温度
- fault 状态
- open circuit
- over / under voltage
- thermocouple range fault

不要只读一个温度值就直接发送到 RS485 或 RaceChrono。

### 9.2 热电偶输入滤波

热电偶线在赛道环境容易收到干扰。

建议前端预留：

```text
T+ 到 GND：10nF 级别
T- 到 GND：10nF 级别
T+ 到 T-：1nF ~ 10nF 级别，视 MAX31856 推荐和实测调整
```

如果暂时没有 10nF，不建议随便用过大的电容长期替代。测试阶段可以不贴或临时验证，但最终版本应按推荐滤波完善。

### 9.3 热电偶安装

热电偶应避免：

- 线束直接被刹车盘磨到
- 热电偶头部松动
- 高温区域没有机械保护
- 线束没有应力释放
- 传感器线和点火 / 电机 / 高电流线束平行太长

## 10. 显示中控 UI 原则

小屏幕版本，例如 1.3 寸 OLED，不要堆太多信息。

优先显示：

```text
大号温度数字
ALM 报警阈值
SET / 保存状态
故障状态 FAIL
RaceChrono/BLE 状态可选，但不要挤占主温度显示
```

如果只显示一个节点，建议不要显示：

- FL / FR 过小标签
- BREAK TEMP FAIL 长文字
- MAX 等无关状态

用户当前偏好：

- 主温度数字尽量大
- `ALM:xxx` 保留
- SET 设置逻辑保留
- 按键响应要及时
- 故障时必须明确，不要误显示正常温度

---

## 11. 按键逻辑建议

常见三按键：

```text
SET
UP
DOWN
```

推荐逻辑：

- 短按 SET：进入 / 退出报警阈值设置，或保存当前阈值
- UP：阈值增加
- DOWN：阈值减少
- 长按 SET：可作为蜂鸣器静音 / 恢复，具体以当前固件为准

重要要求：

- 按键必须去抖
- 按键响应不能被 RS485 读取或 BLE 发送阻塞
- 保存成功应短暂显示 `SAVED`
- 长按动作不能误触发短按保存

---

## 12. 蜂鸣器逻辑建议

必须把蜂鸣器逻辑写清楚，避免现场误判。

推荐状态：

```text
sensorOk       传感器是否正常
commOk         RS485 通信是否正常
bleConnected   RaceChrono 是否连接
tempC          当前温度
alarmTempC     报警阈值
buzzerMuted    是否静音
alarmActive    是否达到报警条件
```

推荐逻辑：

1. 传感器失败时，可以短促提示或显示 FAIL，但不要和超温报警混淆。
2. 温度达到报警阈值且未静音时，蜂鸣器报警。
3. 如果用户长按 SET 静音，是否在新一轮超温时重新响，必须在固件说明中写清楚。
4. 静音不应掩盖屏幕报警状态。
5. RaceChrono 断开不应影响本地超温报警。

建议显示：

```text
BEEP ON
BEEP OFF
ALARM
FAIL
BLE
```

## 13. RaceChrono 与 RS485 的关系

12V RS485 版本必须同时考虑：

```text
RS485 接收/发送 + 本地显示 + 本地蜂鸣器报警 + RaceChrono BLE 数据记录
```

因此：

- RS485 失败不应导致 BLE 任务卡死。
- BLE 未连接不应导致 RS485 显示停止。
- MAX31856 fault 应同时影响 RS485 状态和 RaceChrono 发送状态。
- 异常温度不要发送成 0°C，除非协议明确用 0 表示故障；更推荐发送故障状态或停止更新并在本地显示 FAIL。

如果用户问“RaceChrono 搜索不到设备”，需要检查：

1. 代码是否包含 BLE 初始化。
2. BLE 设备名是否正确。
3. BLE advertising 是否启动。
4. RS485 读取是否阻塞了 BLE。
5. MAX31856 初始化失败是否导致程序卡住。

采集节点建议打印：

```text

[MAX31856] TC=325.4C CJ=38.2C fault=0x00

[BLE] RaceChrono connected
[BLE] send BrakeTemp=325.4C
```

显示中控建议打印：

```text
[BOOT] brake temp alarm display 12V RS485
[RS485] FL addr=0x01 temp=325.4C
[RS485] FR addr=0x02 read FAIL
[DATA] FL=325.4C FR=nanC MAX=325.4C ALM=600
[KEY] SET short -> SAVED
[BUZZER] alarm ON
```

这些日志对现场排查非常重要，不要随意删除。

## 15. 通信失败处理

RS485 读取失败时，显示中控应区分：

```text
正常温度
读取超时
CRC / checksum 错误
节点无响应
传感器 fault
BLE 未连接
```

不要把读取失败直接显示为 `0°C`，因为这会误导驾驶员。

推荐显示：

```text
FAIL
---
NO DATA
BLE OFF
```

推荐数据状态：

```cpp
bool sensorOk;
bool commOk;
bool bleConnected;
float tempC;      // 仅在 sensorOk && 数据有效时使用
uint32_t lastOkMs;
```

## 16. 最小测试流程

### 16.1 采集节点

1. 12V 供电。
2. 测 3.3V 是否稳定。
3. 串口确认 MAX31856 初始化成功。
4. 串口确认 BLE advertising started。
5. RaceChrono Pro 能搜索到设备。
6. RaceChrono Pro 能连接设备并收到刹车温度。
7. 室温读取合理。
8. 热源靠近热电偶，温度上升。
9. RaceChrono 中温度同步上升。
10. 断开热电偶，fault 能识别，RaceChrono 不应误记录为正常 0°C。
11. RS485 发送日志正常。

### 16.2 显示中控

1. 上电显示启动页。
2. RS485 读取节点地址 0x01。
3. 温度正常显示。
4. 断开节点，显示 FAIL。
5. SET / UP / DOWN 按键响应正常。
6. 修改 ALM 后能显示 SAVED。
7. 超过 ALM 后蜂鸣器报警。
8. 长按 SET 静音逻辑符合当前固件定义。
9. RaceChrono 连接 / 断开不影响本地报警显示。

### 16.3 车上测试

1. 发动车辆前测试。
2. 发动车辆后测试。
3. 怠速用电负载变化测试。
4. RaceChrono 保持连接测试。
5. 轻微晃动线束，RS485 不应掉线。
6. 热源接触热电偶，数据不应卡死。
7. RaceChrono 数据不应归 0 或卡死。
8. 长时间运行 20~30 分钟。

## 17. Codex 修改本版本代码时必须遵守

1. 12V RS485 版本也必须支持 RaceChrono 数据发送，除非用户明确要求移除。
2. 不要把 RS485 版本误改成纯本地显示版本。
3. 不要删除 BLE RaceChrono 广播和发送逻辑。
4. 不要删除 MAX31856 fault 日志。
5. 不要把读取失败显示或发送为 0°C。
6. 不要让 RS485 读取阻塞按键响应。
7. 不要让 BLE 发送阻塞 RS485 和显示。
8. 不要让 OLED 刷新阻塞通信。
9. 不要随意改节点地址。
10. 不要随意改蜂鸣器静音逻辑。
11. 修改代码时必须输出完整 `.ino` 文件。
12. 修改后必须说明蜂鸣器逻辑。
13. 修改后必须说明 RaceChrono BLE 是否可搜索、可连接、发送哪些通道。
