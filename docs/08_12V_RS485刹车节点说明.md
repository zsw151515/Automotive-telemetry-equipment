# 08 break_temp_alarm_display_12V_RS485 版本说明

本文件专门记录当前主线之一：**break_temp_alarm_display_12V_RS485**。

重要修正：

> `brake_temp_12v_max31856` 和 `break_temp_alarm_display_12V_RS485` 不是同一个版本，不能混淆。

## 1. 两个版本的边界

### 1.1 brake_temp_12v_max31856

这是一个独立的 MAX31856 + K 型热电偶刹车温度采集版本。

特点：

- 12V 供电
- MAX31856
- K 型热电偶
- 重点关注热电偶输入、MAX31856 fault、电源噪声、EMI
- 不等同于 RS485 报警显示版本

该版本应放在：

```text
firmware/brake_temp_12v_max31856/
hardware/brake_temp_12v_max31856/   // 后续如有需要可单独创建
```

### 1.2 break_temp_alarm_display_12V_RS485

这是当前项目重点维护的 RS485 报警显示版本。

特点：

- 12V 供电系统场景
- 通过 RS485 获取刹车温度数据
- OLED / TFT 显示当前温度
- 显示 `ALM` 报警阈值
- SET / UP / DOWN 按键设置阈值
- 蜂鸣器报警
- 必须支持 RaceChrono Pro 数据发送

该版本应放在：

```text
firmware/brake_temp_alarm_display_12v_rs485/
hardware/brake_temp_12v_rs485/
```

不要把 MAX31856 采集代码直接写进 `break_temp_alarm_display_12V_RS485`，除非用户明确要求做一体化硬件。

---

## 2. break_temp_alarm_display_12V_RS485 的正确架构

当前 RS485 报警显示版本应按下面架构理解：

```text
RS485 温度数据输入
        ↓
数据解析 / 超时判断 / 异常判断
        ↓
同时输出：
  1. OLED / TFT 显示当前刹车温度
  2. 蜂鸣器执行超温报警
  3. BLE 向 RaceChrono Pro 发送刹车温度数据
```

也就是说，**RaceChrono BLE 数据发送应属于 break_temp_alarm_display_12V_RS485 当前版本需求之一**。

如果 RaceChrono 搜索不到设备，应检查这个显示/报警固件是否真的包含：

- BLE 初始化
- BLE advertising
- RaceChrono 可识别的设备名 / Service / Characteristic
- 刹车温度通道发送逻辑

不能因为它叫 RS485 版本，就默认它不需要 RaceChrono。

## 4. RS485 数据来源

`break_temp_alarm_display_12V_RS485` 的温度数据来自 RS485。

RS485 数据源可能是：

- 工业 RS485 温度传感器
- 独立 RS485 刹车温度采集节点
- 其他输出温度数据的 RS485 设备

但显示/报警固件本身的核心职责是：

```text
读 RS485 -> 判断状态 -> 显示 -> 报警 -> 发给 RaceChrono
```

不要默认它板上一定有 MAX31856。

## 5. 典型地址规划

当前项目中曾使用过如下地址概念：

```text
FL addr = 0x01
FR addr = 0x02
```

如果扩展四轮：

```text
FL = 0x01
FR = 0x02
RL = 0x03
RR = 0x04
```

如果只显示一个节点：

```text
BRAKE_NODE_ADDR = 0x01
```

Codex 修改 RS485 代码时，不要随意更改地址映射。若必须更改，必须列出新旧地址对应关系。

## 6. RaceChrono 通道规划

`break_temp_alarm_display_12V_RS485` 必须支持 RaceChrono 数据输出。

最低要求：

```text
BrakeTemp = 当前刹车温度，单位 °C
```

如果双前轮：

```text
BrakeTempFL
BrakeTempFR
BrakeTempMax
```

如果四轮：

```text
BrakeTempFL
BrakeTempFR
BrakeTempRL
BrakeTempRR
BrakeTempMax
```

## 7. RaceChrono BLE 注意事项

不要随意修改：

- BLE 设备名
- Service UUID
- Characteristic UUID
- 数据包格式
- RaceChrono 可识别的通道 ID / PID / CAN ID
- 发送频率

如果当前 RaceChrono 搜索不到设备，优先检查：

1. 是否真的启动 BLE advertising。
2. 固件是否卡在 RS485 初始化或读取流程。
3. RS485 读取超时是否阻塞 BLE。
4. BLE 设备名是否符合 RaceChrono 配置。
5. 手机端是否需要删除旧设备或重启 RaceChrono。

## 8. RS485 通信方式说明

RS485 是物理层，不等于协议本身。

本项目 RS485 版本可能采用两种方式之一。

### 8.1 简单自定义串口协议

例如节点周期发送：

```text
ADDR,TEMP,STATUS\n
```

或中控轮询：

```text
REQ,01\n
```

设备回复：

```text
01,325.4,OK\n
```

优点：

- 代码简单
- 调试方便
- 串口工具可直接看

缺点：

- 抗干扰和错误校验需要自己做
- 多节点时需要处理冲突

### 8.2 Modbus RTU 风格

如果使用 Modbus RTU，应明确：

- 从机地址
- 波特率
- 校验位
- 寄存器地址
- 温度缩放比例
- CRC 校验

### 8.3 当前建议

项目当前阶段建议优先使用：

```text
简单轮询 + 明确地址 + 超时 + checksum / CRC
```

不要一开始就引入过度复杂协议。

## 9. 任务时序建议

`break_temp_alarm_display_12V_RS485` 同时承担 RS485、显示、按键、蜂鸣器、BLE RaceChrono 时，必须避免互相阻塞。

推荐节奏：

```text
RS485 读取：5~10Hz 或按传感器实际响应调整
RaceChrono BLE 发送：5~10Hz，优先稳定
OLED/TFT 刷新：5~10Hz，不要阻塞通信
按键扫描：20~50ms 级别
蜂鸣器任务：非阻塞节奏控制
```

不要使用长时间 `delay()`。

推荐状态机：

```text
RS485 读取任务
BLE RaceChrono 任务
显示任务
按键任务
蜂鸣器任务
故障状态任务
```

每个任务用 `millis()` 调度。

## 10. RS485 物理层设计注意事项

### 10.1 A/B 线

必须确保：

- A/B 不接反
- GND 参考线可靠
- 线束固定牢固
- 接插件抗震

很多 RS485 模块对 A/B 标注可能和其他厂家相反，现场调试时如果完全无响应，应尝试交换 A/B。

### 10.2 终端电阻

如果线较长或环境噪声大，建议总线两端加 120Ω 终端电阻。

线很短、只有一个节点时，终端电阻可根据实测决定。

不要在每个节点都加 120Ω，否则总线负载会过重。

### 10.3 偏置电阻

总线空闲状态需要稳定电平。

建议在主机端或总线一端考虑：

- A 上拉
- B 下拉
- 或使用带 fail-safe 的 RS485 收发器

### 10.4 GND 参考

车载环境下只接 A/B 有时不稳定，建议 RS485 线束同时带 GND 参考线。

典型线束：

```text
12V
GND
RS485_A
RS485_B
```

## 11. 显示中控 UI 原则

小屏幕版本，例如 1.3 寸 OLED，不要堆太多信息。

优先显示：

```text
大号温度数字
ALM 报警阈值
SET / 保存状态
故障状态 FAIL
RaceChrono/BLE 状态可选，但不要挤占主温度显示
```

如果只显示一个节点，建议不要显示：

- FL / FR 过小标签
- BREAK TEMP FAIL 长文字
- MAX 等无关状态

用户当前偏好：

- 主温度数字尽量大
- `ALM:xxx` 保留
- SET 设置逻辑保留
- 按键响应要及时
- 故障时必须明确，不要误显示正常温度

## 12. 按键逻辑建议

常见三按键：

```text
SET
UP
DOWN
```

推荐逻辑：

- 短按 SET：进入 / 退出报警阈值设置，或保存当前阈值
- UP：阈值增加
- DOWN：阈值减少
- 长按 SET：可作为蜂鸣器静音 / 恢复，具体以当前固件为准

重要要求：

- 按键必须去抖
- 按键响应不能被 RS485 读取或 BLE 发送阻塞
- 保存成功应短暂显示 `SAVED`
- 长按动作不能误触发短按保存

---

## 13. 蜂鸣器逻辑建议

必须把蜂鸣器逻辑写清楚，避免现场误判。

推荐状态：

```text
commOk         RS485 通信是否正常
bleConnected   RaceChrono 是否连接
tempValid      温度数据是否有效
tempC          当前温度
alarmTempC     报警阈值
buzzerMuted    是否静音
alarmActive    是否达到报警条件
```

推荐逻辑：

1. RS485 读取失败时，可以短促提示或显示 FAIL，但不要和超温报警混淆。
2. 温度达到报警阈值且未静音时，蜂鸣器报警。
3. 如果用户长按 SET 静音，是否在新一轮超温时重新响，必须在固件说明中写清楚。
4. 静音不应掩盖屏幕报警状态。
5. RaceChrono 断开不应影响本地超温报警。

---

## 14. 通信失败处理

RS485 读取失败时，显示中控应区分：

```text
正常温度
读取超时
CRC / checksum 错误
设备无响应
温度数据无效
BLE 未连接
```

不要把读取失败直接显示为 `0°C`，因为这会误导驾驶员。

推荐显示：

```text
FAIL
---
NO DATA
BLE OFF
```

推荐数据状态：

```cpp
bool commOk;
bool bleConnected;
bool tempValid;
float tempC;      // 仅在 tempValid && commOk 时使用
uint32_t lastOkMs;
```

## 15. 最小测试流程

### 15.1 RS485 / 显示

1. 上电显示启动页。
2. RS485 读取地址 0x01 或当前配置地址。
3. 温度正常显示。
4. 断开 RS485 数据源，显示 FAIL。
5. SET / UP / DOWN 按键响应正常。
6. 修改 ALM 后能显示 SAVED。
7. 超过 ALM 后蜂鸣器报警。
8. 长按 SET 静音逻辑符合当前固件定义。

### 15.2 RaceChrono

1. 串口确认 BLE advertising started。
2. RaceChrono Pro 能搜索到设备。
3. RaceChrono Pro 能连接设备并收到刹车温度。
4. RS485 温度上升时，RaceChrono 中温度同步上升。
5. RS485 断开或数据无效时，RaceChrono 不应误记录为正常 0°C。
6. RaceChrono 连接 / 断开不影响本地报警显示。

### 15.3 车上测试

1. 发动车辆前测试。
2. 发动车辆后测试。
3. 怠速用电负载变化测试。
4. RaceChrono 保持连接测试。
5. 轻微晃动线束，RS485 不应掉线。
6. 长时间运行 20~30 分钟。

## 16. Codex 修改本版本代码时必须遵守

1. `break_temp_alarm_display_12V_RS485` 不是 `brake_temp_12v_max31856`。
2. 不要把 MAX31856 采集逻辑混入本版本，除非用户明确要求一体化。
3. 本版本必须支持 RaceChrono 数据发送，除非用户明确要求移除。
4. 不要把本版本改成纯 RS485 显示版本。
5. 不要删除 BLE RaceChrono 广播和发送逻辑。
6. 不要把读取失败显示或发送为 0°C。
7. 不要让 RS485 读取阻塞按键响应。
8. 不要让 BLE 发送阻塞 RS485 和显示。
9. 不要让 OLED 刷新阻塞通信。
10. 不要随意改节点地址。
11. 不要随意改蜂鸣器静音逻辑。
12. 修改代码时必须输出完整 `.ino` 文件。
13. 修改后必须说明蜂鸣器逻辑。
14. 修改后必须说明 RaceChrono BLE 是否可搜索、可连接、发送哪些通道。
