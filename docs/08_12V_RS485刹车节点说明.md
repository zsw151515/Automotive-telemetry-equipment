# 08 break_temp_alarm_display_12V_RS485 版本说明

本文件专门记录当前主线之一：**break_temp_alarm_display_12V_RS485**。

重要边界：

> `brake_temp_12v_max31856` 和 `break_temp_alarm_display_12V_RS485` 不是同一个版本，不能混淆。

## 1. 两个版本的边界

### 1.1 brake_temp_12v_max31856

这是一个独立的 MAX31856 + K 型热电偶刹车温度采集版本。

特点：

- 12V 供电
- MAX31856
- K 型热电偶
- 测量目标：**卡钳温度**
- 当前还没有接入报警显示
- 重点关注热电偶输入、MAX31856 fault、电源噪声、EMI
- 不等同于 RS485 报警显示版本

该版本应放在：

```text
firmware/brake_temp_12v_max31856/
```

### 1.2 break_temp_alarm_display_12V_RS485

这是当前项目重点维护的 RS485 报警显示版本。

特点：

- 使用 RS485 通信方式的红外测温传感器
- 测量目标：**刹车盘温度**
- OLED / TFT 显示当前刹车盘温度
- 显示 `ALM` 报警阈值
- SET / UP / DOWN 按键设置阈值
- 蜂鸣器报警
- 必须支持 RaceChrono Pro 数据发送
- 不使用 MAX31856 热电偶测温逻辑

该版本应放在：

```text
firmware/brake_temp_alarm_display_12v_rs485/
hardware/brake_temp_12v_rs485/
```

不要把 MAX31856 采集代码直接写进 `break_temp_alarm_display_12V_RS485`，除非用户明确要求做一体化硬件。

## 2. RS485 红外测温传感器背景

`break_temp_alarm_display_12V_RS485` 使用的是 RS485 通信方式的红外测温传感器，用于非接触测量刹车盘温度。

当前传感器手册要点：

- 固定式红外测温仪
- 红外非接触测温
- 适合长距离、较强干扰的工业环境安装
- 不锈钢外壳
- 保护等级 IP65
- 工作电源：RS485 型号为 5~36V DC
- RS485 输出协议：Modbus RTU
- 默认地址：0x01
- 默认波特率：9600
- 默认通信格式：1 位起始位、8 位数据位、无校验、1 位停止位
- 默认读取功能码：0x03
- 温度寄存器：起始地址 0x0000，读取 1 个寄存器
- 返回温度为有符号 16 位整数，实际温度 = 返回值 / 10
- 地址修改寄存器：0x07A0，功能码 0x06

典型读取温度命令：

```text
01 03 00 00 00 01 84 0A
```

典型返回：

```text
01 03 02 03 E8 B8 FA
```

其中 `0x03E8 = 1000`，实际温度为：

```text
1000 / 10 = 100.0°C
```

## 3. break_temp_alarm_display_12V_RS485 的正确架构

当前 RS485 报警显示版本应按下面架构理解：

```text
RS485 红外测温传感器读取刹车盘温度
        ↓
Modbus RTU 解析 / CRC 校验 / 超时判断 / 异常判断
        ↓
同时输出：
  1. OLED / TFT 显示当前刹车盘温度
  2. 蜂鸣器执行超温报警
  3. BLE 向 RaceChrono Pro 发送刹车盘温度数据
```

也就是说，**RaceChrono BLE 数据发送应属于 break_temp_alarm_display_12V_RS485 当前版本需求之一**。

如果 RaceChrono 搜索不到设备，应检查这个显示/报警固件是否真的包含：

- BLE 初始化
- BLE advertising
- RaceChrono 可识别的设备名 / Service / Characteristic
- 刹车盘温度通道发送逻辑

不能因为它叫 RS485 版本，就默认它不需要 RaceChrono。

最低要求：

```text

```

```text

BrakeDiscTempFR

```


## 8. RaceChrono BLE 注意事项

不要随意修改：

- BLE 设备名
- Service UUID
- Characteristic UUID
- 数据包格式
- RaceChrono 可识别的通道 ID / PID / CAN ID
- 发送频率

如果当前 RaceChrono 搜索不到设备，优先检查：

1. 是否真的启动 BLE advertising。
2. 固件是否卡在 RS485 初始化或读取流程。
3. RS485 读取超时是否阻塞 BLE。
4. BLE 设备名是否符合 RaceChrono 配置。
5. 手机端是否需要删除旧设备或重启 RaceChrono。

## 9. RS485 Modbus RTU 通信说明

当前红外测温传感器使用 RS485 Modbus RTU。

默认参数：

```text
地址：0x01
波特率：9600
数据位：8
校验：无
停止位：1
功能码：0x03 读取温度
温度寄存器：0x0000
读取长度：0x0001
温度缩放：返回整数 / 10 = 摄氏度
```

典型读温度帧：

```text
01 03 00 00 00 01 84 0A
```

典型返回帧：

```text
01 03 02 03 E8 B8 FA
```

异常处理：

- CRC 错误：判定读取失败
- 超时：判定读取失败
- 地址不匹配：丢弃
- 功能码不匹配：丢弃
- 数据长度不匹配：丢弃
- 温度超出合理范围：标记无效，不要显示或发送为正常 0°C

## 10. 任务时序建议

`break_temp_alarm_display_12V_RS485` 同时承担 RS485、显示、按键、蜂鸣器、BLE RaceChrono 时，必须避免互相阻塞。

推荐节奏：

```text
RS485 读取：5~10Hz 或按传感器实际响应调整
RaceChrono BLE 发送：5~10Hz，优先稳定
OLED/TFT 刷新：5~10Hz，不要阻塞通信
按键扫描：20~50ms 级别
蜂鸣器任务：非阻塞节奏控制
```

不要使用长时间 `delay()`。

推荐状态机：

```text
RS485 Modbus 读取任务
BLE RaceChrono 任务
显示任务
按键任务
蜂鸣器任务
故障状态任务
```

每个任务用 `millis()` 调度。

## 11. RS485 物理层设计注意事项

### 11.1 A/B 线

必须确保：

- A/B 不接反
- GND 参考线可靠
- 线束固定牢固
- 接插件抗震

很多 RS485 模块对 A/B 标注可能和其他厂家相反，现场调试时如果完全无响应，应尝试交换 A/B。

### 11.2 传感器线色

根据当前红外测温仪手册，RS485 型号线色：

```text
红色：5~36V DC+
黑色：0V
绿色：RS485 A+ (T/R+)
黄色：RS485 B- (T/R-)
银色：屏蔽线
```

### 11.3 终端电阻

如果线较长或环境噪声大，建议总线两端加 120Ω 终端电阻。

线很短、只有一个节点时，终端电阻可根据实测决定。

不要在每个节点都加 120Ω，否则总线负载会过重。

### 11.4 偏置电阻

总线空闲状态需要稳定电平。

建议在主机端或总线一端考虑：

- A 上拉
- B 下拉
- 或使用带 fail-safe 的 RS485 收发器

### 11.5 GND 与屏蔽

车载环境下只接 A/B 有时不稳定，建议 RS485 线束同时带 GND 参考线。

传感器屏蔽线应根据整车接地方案良好接地，避免形成干扰。

典型线束：

```text
12V / 5V 供电正
GND
RS485_A
RS485_B
屏蔽线
```

## 12. 红外测温安装注意事项

### 12.1 测量目标

该版本测量目标是：

```text
刹车盘表面温度
```

不要把数据命名成卡钳温度。

### 12.2 视场与距离

当前红外测温仪光学分辨率为 20:1。

原则：

```text
测量目标尺寸必须大于测量视场
```

赛道环境有震动，目标尺寸应留足余量，避免传感器晃动后看见刹车盘外的其他物体。

### 12.3 光路无遮挡

安装时必须保证传感器到刹车盘的光路无遮挡。

避免：

- 支架遮挡
- 导风板遮挡
- 轮圈结构遮挡
- 线束遮挡
- 灰尘 / 油污污染镜头

### 12.4 镜头清洁

镜头灰尘、烟尘和油污会降低测量精度。

应定期检查镜头，必要时用合适方式清洁。

### 12.5 电磁干扰

传感器应尽量远离：

- 电机
- 点火高压线
- 大电流电缆
- 强干扰源

必要时可加强屏蔽和接地。

## 13. 显示中控 UI 原则

小屏幕版本，例如 1.3 寸 OLED，不要堆太多信息。

优先显示：

```text
大号刹车盘温度数字
ALM 报警阈值
SET / 保存状态
故障状态 FAIL
RaceChrono/BLE 状态可选，但不要挤占主温度显示
```

如果只显示一个节点，建议不要显示：

- FL / FR 过小标签
- BREAK TEMP FAIL 长文字
- MAX 等无关状态

用户当前偏好：

- 主温度数字尽量大
- `ALM:xxx` 保留
- SET 设置逻辑保留
- 按键响应要及时
- 故障时必须明确，不要误显示正常温度

## 14. 按键逻辑建议

常见三按键：

```text
SET
UP
DOWN
```

推荐逻辑：

- 短按 SET：进入 / 退出报警阈值设置，或保存当前阈值
- UP：阈值增加
- DOWN：阈值减少
- 长按 SET：可作为蜂鸣器静音 / 恢复，具体以当前固件为准

重要要求：

- 按键必须去抖
- 按键响应不能被 RS485 读取或 BLE 发送阻塞
- 保存成功应短暂显示 `SAVED`
- 长按动作不能误触发短按保存

---

## 15. 蜂鸣器逻辑建议

必须把蜂鸣器逻辑写清楚，避免现场误判。

推荐状态：

```text
commOk         RS485 通信是否正常
bleConnected   RaceChrono 是否连接
tempValid      温度数据是否有效
discTempC      当前刹车盘温度
alarmTempC     报警阈值
buzzerMuted    是否静音
alarmActive    是否达到报警条件
```

推荐逻辑：

1. RS485 读取失败时，可以短促提示或显示 FAIL，但不要和超温报警混淆。
2. 刹车盘温度达到报警阈值且未静音时，蜂鸣器报警。
3. 如果用户长按 SET 静音，是否在新一轮超温时重新响，必须在固件说明中写清楚。
4. 静音不应掩盖屏幕报警状态。
5. RaceChrono 断开不应影响本地超温报警。

## 16. 通信失败处理

RS485 读取失败时，显示中控应区分：

```text
正常温度
读取超时
CRC 错误
设备无响应
温度数据无效
BLE 未连接
```

不要把读取失败直接显示为 `0°C`，因为这会误导驾驶员。

推荐显示：

```text
FAIL
---
NO DATA
BLE OFF
```

推荐数据状态：

```cpp
bool commOk;
bool bleConnected;
bool tempValid;
float discTempC;  // 仅在 tempValid && commOk 时使用
uint32_t lastOkMs;
```

## 17. 最小测试流程

### 17.1 RS485 / 显示

1. 上电显示启动页。
2. RS485 读取地址 0x01 或当前配置地址。
3. 刹车盘温度正常显示。
4. 断开 RS485 传感器，显示 FAIL。
5. SET / UP / DOWN 按键响应正常。
6. 修改 ALM 后能显示 SAVED。
7. 超过 ALM 后蜂鸣器报警。
8. 长按 SET 静音逻辑符合当前固件定义。

### 17.2 RaceChrono

1. 串口确认 BLE advertising started。
2. RaceChrono Pro 能搜索到设备。
3. RaceChrono Pro 能连接设备并收到刹车盘温度。
4. RS485 红外传感器温度上升时，RaceChrono 中温度同步上升。
5. RS485 断开或数据无效时，RaceChrono 不应误记录为正常 0°C。
6. RaceChrono 连接 / 断开不影响本地报警显示。

### 17.3 车上测试

1. 发动车辆前测试。
2. 发动车辆后测试。
3. 怠速用电负载变化测试。
4. RaceChrono 保持连接测试。
5. 轻微晃动线束，RS485 不应掉线。
6. 刹车盘升温时，显示和 RaceChrono 温度同步变化。
7. 长时间运行 20~30 分钟。
