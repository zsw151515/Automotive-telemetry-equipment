# 11 四路有线胎温中控接口

状态：离线研发，硬件关卡未通过。本方向独立于无线胎温高度 v3 和刹车报警节点。

## 成品探头解析基线

按手册读取地址 0x01、功能码 0x65、起始寄存器 0x0000、785 个寄存器。假设响应寄存器字节数 1570，总帧长 1576，像素位于寄存器 0x0010 至 0x030F，按行排列，32 列、24 行。

寄存器使用大端有符号 16 位计数，温度等于计数除以 10，单位摄氏度；CRC16 低字节在前。原始温度保留，手册范围 -40 至 300°C 之外的像素标记无效。无效状态与 0°C 独立，零温度可以正常有效。

当前仅通过合成帧测试，这些协议参数尚未与实物核对。默认波特率、4/5 Hz、全帧长度、快照一致性等以 validation_probe.md 的真实证据关闭，不能写成已验证。

## 只读采集

运行 scripts/capture_yf90640.py --list-ports 列举串口；用户确认对应端口和参数后，显式提供 --port、--baud、--stopbits、--seconds 和全新的 --output 目录。工具不写配置、不广播、不自动枚举轮询串口。

每条 JSONL 保留原始收发字节和主机单调接收时间。metadata.json 区分 captured 与 error，hardware_validated 始终为 false；“采集成功”不等于“探头正确”。现阶段不连接或操作真实端口。

## 八分区离线算法

每区 4 列、ROI 高 8 行，最少 18 个有效像素，均值每侧裁剪 3 个样本。分区有效域 -20 至 200°C，与探头完整热图的原始范围分开处理。配置镜像/版本变化或超过 1500 ms 的间隔会重新初始化滤波；重复/倒退时间不发布分区结果。

参考代码搜索起始行配置为 3–17，但 24 行中放置 8 行 ROI 的实际最大起始行是 16，沿用其边界裁剪。跟踪速率从逐帧 1 行改为以 34 ms 为参考的按时间限制，低通系数也按实际 dt 换算，避免每秒约四帧输入仍按高速采样节奏处理。

变化率基线 160°C/s，死区 0.06°C，跃变阈值 12°C。原参考代码跃变分支与普通分支使用相同限速；新离线实现保留限速，并将跃变时的参考低通系数上限设为 0.45，再按实际 dt 换算。该保守策略可能改变跟手性，必须通过真实热源实验确认，当前仅有离线测试证据。

## RejsaRubberTrac BLE 编码

设备名格式 RejsaRubber + FL/FR/RL/RR + 蓝牙地址末三字节的六位十六进制后缀；服务 0x1FF7，特征 0x0001、0x0002、0x0003，分别为 20 字节。这是热图协议，不是 DIY CAN，不定义 PID。

每特征 B0=0x02；B4–B19 是八个有符号小端 16 位温度计数，温度°C=计数/10。B1–B3 由 LegacyAuxFields 的相应原始字节提供，原协议中的高度、电量、电压不再作为本系统测量值。

目前未冻结这些辅助字段的生产编码，硬件 profile 必须完成手机实测后显式核准。未核准时不启用 BLE。仅连接就绪、等待启动保护时间、八分区全部有效、轮位正确且数据年龄不超过 1500 ms 时通知；停发不等于手机自动清空最后值，必须实测记录。

## SPI 事务与数据年龄

首版实现采用等长 1728 字节全双工事务。主机发送请求：B0=0x52，B1=轮位，B2–B5=小端 token，B6–B7=前六字节的 Modbus CRC16，其余为零；从机返回此前准备的快照。初次旧 token/空响应被丢弃，同一 token 在 100 ms 窗口内继续读取，直到匹配或超时。P4 启动时随机化 token 起点，降低重启后命中旧排队响应的风险。

这种方式避免变长请求/响应阶段的重新同步，代价是额外的事务和带宽。SPI 为 1 MHz mode 0、四路独立片选与就绪信号，异步 DMA，每次 poll 不等待整个传输。单路未就绪不会阻塞其余轮位。发送缓冲通过租约冻结至 DMA 完成；在途不允许重新编码。

屏幕数据总年龄保守取“从机准备时年龄＋请求到响应耗时＋接收后主机经过时间”，向上取整并饱和到 u32；不使用从机绝对时间减主机时间，也不因重读旧矩阵刷新有效期。真实时序和吞吐仍未验证。
